# 00 — 정답표 생성 (평가자 영역)

> 이 결과는 `hidden/ground_truth.json` 에 저장된다. 파이프라인(10~70)은 이 파일을 볼 수 없다. 이 정답표로 합성 원문을 만들고(01), 파이프라인이 구조를 얼마나 되찾는지 채점한다(90).

너는 사용자 조사 실험의 **정답을 심는 사람**이다. 아래 탐색 과제(brief)를 보고, 사람들의 행동 밑에 깔린 **욕구 충돌(tension)** 6개를 정한다. 나중에 다른 시스템이 원문만 보고 이 tension 들을 찾아내야 한다.

## 탐색 과제

{
  "domain": "주방에서의 식재료 관리·장보기·요리와 가족 간 소통 — 냉장고 화면과 주변 서비스",
  "device": "패밀리허브 냉장고",
  "device_traits": [
    "문에 달린 큰 터치 화면",
    "주방에 항상 켜져 있음",
    "가족 모두가 지나가며 봄",
    "음성 입력",
    "내부 카메라"
  ],
  "surroundings": [
    "스마트폰",
    "장보기",
    "배달 앱",
    "가족 메신저",
    "레시피 앱",
    "캘린더"
  ],
  "exclude": [
    "특정 회사 내부 정보",
    "실존 인물 특정"
  ],
  "note": "파이프라인에 공개되는 탐색 과제. 정답 tension 을 적지 않는다."
}

## 규칙

1. tension 은 **두 욕구의 충돌**이다. `pole_a`·`pole_b` 는 각각 "~하고 싶다 / ~는 싫다" 꼴의 욕구 문장. 기능 요구("~기능이 필요하다")가 아니다.
2. 6개 중 **3개는 familiar**(이 분야를 아는 사람이면 떠올릴 법한 것), **3개는 unfamiliar**(흔한 글·기사에서 잘 다뤄지지 않지만 실제 행동에서 드러날 법한 것). unfamiliar 가 이 실험의 핵심이다. 뻔한 것을 unfamiliar 로 표시하지 않는다.
3. 6개는 서로 **겹치지 않아야** 한다. 같은 행동이 두 tension 에 똑같이 들어갈 수 있으면 하나를 바꾼다.
4. `principle` 은 그 충돌을 푸는 설계 원리 한 문장(해법 기능이 아니라 방향).
5. `behavior_seeds` 는 tension 마다 3개. 이 충돌 때문에 사람들이 실제로 하는 **관찰 가능한 행동**(회피·우회·습관 포함). 욕구 문장의 단어를 그대로 쓰지 않는다.
6. `distractor_themes` 6개: 같은 분야에서 사람들이 자주 말하지만 **어떤 tension 과도 무관한** 주제(기기 불만, 가격, 잡담 등).
7. 특정 회사 내부 정보·실존 인물은 쓰지 않는다. brief 의 `exclude` 를 따른다.

## 출력

설명 없이 **한 줄 JSON 하나**만.

```json
{"domain":"...","note":"자동 생성 정답표","tensions":[{"id":"HT_01","pole_a":"...","pole_b":"...","principle":"...","familiarity":"familiar","behavior_seeds":["...","...","..."]}],"distractor_themes":["..."]}
```
