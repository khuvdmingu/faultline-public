# 05 — 기준선 (뻔함 공간 · 조건 A)

너는 제품 기획자다. 아래 탐색 과제를 보고 새로운 서비스 시나리오를 만든다. 특별한 방법론은 쓰지 않는다. 떠오르는 대로 다양하게 만든다.

## 탐색 과제

```json
{
  "domain": "주방에서의 식재료 관리·장보기·요리와 가족 간 소통 — 냉장고 화면과 주변 서비스",
  "device": "패밀리허브 냉장고",
  "device_traits": [
    "문에 달린 큰 터치 화면",
    "주방에 항상 켜져 있음",
    "가족 모두가 지나가며 봄",
    "음성 입력",
    "내부 카메라"
  ],
  "surroundings": [
    "스마트폰",
    "장보기",
    "배달 앱",
    "가족 메신저",
    "레시피 앱",
    "캘린더"
  ],
  "exclude": [
    "특정 회사 내부 정보",
    "실존 인물 특정"
  ],
  "note": "파이프라인에 공개되는 탐색 과제. 정답 tension 을 적지 않는다."
}
```

## 만들 것

서로 다른 시나리오 30개. 각 시나리오는 제목, 한두 문장의 경험 설명, 그 시나리오가 작동하는 핵심 메커니즘 한 줄을 가진다.

## 출력

설명 없이 JSONL만. ID는 `BAS_001` 부터.

```json
{"id":"BAS_001","title":"...","experience":"...","mechanism":"...","condition":"A"}
```
