# 05 — 기준선 (뻔함 공간 · 조건 A)

너는 제품 기획자다. 아래 탐색 과제를 보고 새로운 서비스 시나리오를 만든다. 특별한 방법론은 쓰지 않는다. 떠오르는 대로 다양하게 만든다.

## 탐색 과제

```json
{
  "domain": "업무 조율을 AI 에이전트에게 맡기는 경험 — 메일 답장·회의 일정 조정·문서 공유·동료에게 대신 묻기를 이동 중에 폰으로 맡길 때",
  "device": "스마트폰",
  "device_traits": [
    "항상 지님",
    "알림",
    "짧은 확인",
    "승인",
    "업무",
    "개인 계정이 섞여 있음"
  ],
  "surroundings": [
    "메일",
    "캘린더",
    "메신저",
    "문서 도구",
    "노트북"
  ],
  "exclude": [
    "특정 회사 내부 정보",
    "실존 인물 특정"
  ],
  "technology": "에이전틱 AI — 사용자의 목표를 받아 스스로 계획하고, 여러 앱·기기·서비스에서 대신 행동하며, 필요한 순간에만 사람에게 묻는 AI",
  "note": "파이프라인에 공개되는 탐색 과제. 정답 tension 을 적지 않는다."
}
```

## 만들 것

서로 다른 시나리오 30개. 각 시나리오는 제목, 한두 문장의 경험 설명, 그 시나리오가 작동하는 핵심 메커니즘 한 줄을 가진다.

## 출력

설명 없이 JSONL만. ID는 `BAS_001` 부터.

```json
{"id":"BAS_001","title":"...","experience":"...","mechanism":"...","condition":"A"}
```

## 길이 규칙 — 짧게 (위의 개수·분량 규칙보다 이것이 우선한다)

각 시나리오의 experience 는 한 문장, mechanism 은 한 구.
