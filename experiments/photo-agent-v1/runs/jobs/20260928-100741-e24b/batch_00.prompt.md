# 05 — 기준선 (뻔함 공간 · 조건 A)

너는 제품 기획자다. 아래 탐색 과제를 보고 새로운 서비스 시나리오를 만든다. 특별한 방법론은 쓰지 않는다. 떠오르는 대로 다양하게 만든다.

```json
{
  "domain": "사진·영상·기록을 AI 에이전트가 정리하고, 누구에게 무엇을 공유할지 대신 판단하는 경험 — 추억 앨범 만들기·가족·친구 공유·오래된 기록 지우기",
  "device": "스마트폰",
  "device_traits": [
    "카메라",
    "수천 장의 사진 보관함",
    "위치",
    "시간 기록",
    "메신저",
    "SNS 계정"
  ],
  "surroundings": [
    "클라우드 사진 보관함",
    "가족 단톡방",
    "SNS",
    "스마트워치"

```

## 만들 것

서로 다른 시나리오 15개. 각 시나리오는 제목, 한두 문장의 경험 설명, 그 시나리오가 작동하는 핵심 메커니즘 한 줄을 가진다.

## 출력

설명 없이 JSONL만. ID는 `BAS_001` 부터.

```json
{"id":"BAS_001","title":"...","experience":"...","mechanism":"...","condition":"A"}
```

## 길이 규칙 — 짧게 (위의 개수·분량 규칙보다 이것이 우선한다)

각 시나리오의 experience 는 한 문장, mechanism 은 한 구.
