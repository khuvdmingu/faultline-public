준비된 것

  • 판단을 원자 질문으로 쪼갠 질문 은행 3종과 버전 관리
  • 타입과 선택지 수(≤255) 검사, 구조화된 상태 빌더
  • 확률을 결정으로 바꾸는 규칙과 검토 이유
  • 백엔드 교체 인터페이스와 사용량·지연 기록
  • Jev의 보정 주장을 재는 측정기

Jev를 받으면 할 일

  1. JevBackend._client()를 공식 문서대로 채운다
  2. 미확인 가정 두 개(Choice·Score 생성자)를 확인한다
  3. --limit 5로 형식만 본 뒤 전체 실행
  4. logprobs 백엔드와 보정 표를 나란히 비교한다

MVP에 붙이는 순서

  1. 기준선 먼저. 모듈 없이 Phase 0을 한 번 돌린다 (기존 20_link로 한 번에 묶기). 이 점수가 없으면 모듈이 무엇을 바꿨는지 분리할 수 없다.
  2. B 자리 열기. judge/attach/20a_tension_candidates.md를 prompts/로 옮기고 pack.py에 등록 → 20a 실행 → tension_candidates.jsonl.
  3. python3 -m judge run assign --emit-tensions → 결과를 검토한 뒤 data/linked/tensions.jsonl로 복사 → validate.py → score.py.
  4. 같은 corpus로 연결 지표 4개를 기준선과 비교한다. 두 회차씩.
  5. 그다음 A를 붙여 추출 지표를 비교한다. C는 실데이터(Phase 1)부터.

파이프라인 실행(10~40, 20a)은 이 모듈을 만든 세션이 아닌 새 세션에서 한다. 이 세션은 tv-v1의 숨은 정답표를 봤다.
